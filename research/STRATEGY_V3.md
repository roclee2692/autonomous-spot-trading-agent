# 现货波动策略 V3.0

更新：2026-10-12
用途：供人工执行、AI Agent 或自动化程序完整理解并执行。
地位：本文件**完整取代** V2.0。V2.0 中没有出现在本文件里的规则一律作废（作废清单见第 15 条）。

---

## 0. 一句话

每个币一个**固定预算的子账户**，所有币用**同一套规则**：

- 下方挂三张等额买单。
- 下面成交，就更新上面；上面成交，就更新下面。
- 涨到成本 +25% 时卖掉 75%，剩下 25% 作为尾仓，等它翻倍再卖。
- 深跌时最多补三代。第三代挂完就不再加。

---

## 1. 不变的原则

1. 只做现货。不用杠杆、合约或永续。
2. 不预测涨跌，不抄底，不逃顶，不追涨。
3. 全部用提前挂好的限价单。大部分时间什么都不做。
4. 基本面失效的优先级高于一切价格规则（见第 10 条）。
5. 合理优于理论最优；能长期执行优于精确但脆弱。

---

## 2. 币池与角色

| 角色 | 币 | 规则 | 预算 |
|---|---|---|---|
| 核心 | TAO、AAVE、LINK、HYPE | 本文件全部规则 | 大（G_core） |
| 卫星 | NEAR、ZRO、PENDLE、RENDER | **与核心完全相同** | 小（G_sat ≈ G_core / 4） |

- 核心和卫星的唯一区别是预算大小。不再有单独的卫星规则（V2 的 FAST、+20% 卖 75% 加回补这一套已删除）。
- 角色调整不看近期涨幅、反弹力度、循环次数这类价格表现，只在年度复核（第 13 条）里看基本面、流动性和上市时长。

---

## 3. 预算（MAX_CAMPAIGN_BUDGET）

每个币的活动预算：

```
B = 3 × G + S
G = 一代三张买单的合计金额
S = 插针单金额 ≈ 0.25 × G
```

示例：核心 G = $200，S = $50，B = $650。卫星 G = $50，S ≈ $12，B ≈ $160。

规则：

1. 任何时刻都要满足：该币未成交买单 + 已成交未卖出部分的成本 + 尚未挂出的后续代数预算 ≤ B。
2. 子账户不从其他币或外部现金自动补钱。卖出所得回到本币子账户，下一轮自动滚入（第 7 条）。
3. 要增加某币的 B，只能由人决定，并且只在新一轮开始（新锚点）时生效。
4. 单张买单不足 $10 时，不要挂更小的单（Binance 最小下单额为 5 USDT，还要给手续费和尾仓卖出留余量）。应当提高该币的 G，或者不纳入这个币。卫星的 G 不低于 $30。
5. 组合检查：ΣB 必须小于等于"全部变成币之后再跌 50% 我也能拿住"的金额。极端行情里，所有 B 都可能被成交。

---

## 4. 状态变量（每个币）

| 变量 | 含义 |
|---|---|
| A | 当前锚点 |
| C | 本轮加权平均成本。本轮所有成交合并计算，包括第 2、3 代 |
| Q | 本轮持仓数量 |
| GEN | 当前代数（1–3） |
| TAIL lots | 尾仓批次。每个 lot 有自己的成本 C_lot 和卖单 2×C_lot |
| SPIKE | 插针单状态 |

状态：WAIT（只有挂单）、BUILD（本轮有持仓）、PAUSED（基本面暂停）。

---

## 5. 买入：每代三张等额买单

1. 每代挂 3 张买单，每张 G/3：
   - B1 = A × 0.93（−7%）
   - B2 = A × 0.83（−17%）
   - B3 = A × 0.65（−35%）

   所有币用同一组百分比，不按币种另定。
2. **第一张成交之前**：如果某天日收盘价 ≥ 1.20 × A，就以该收盘价作为新的 A，撤掉旧单重挂。这是慢速上调，不因为一天涨 5% 就调整。
3. **第一张成交之后**：A 冻结，不再下移。
4. 每当有买单成交：重算 C，撤旧卖单，按第 6 条重挂卖单。不撤本代其余买单。

---

## 6. 卖出：一次止盈，加一个会退出的尾仓

1. **TP = 1.25 × C**，卖出本轮持仓 Q 的 **75%**。
2. 剩下的 25% 立即成为一个尾仓 lot，成本记为 C_lot = C。同时挂卖单 **2.00 × C_lot**，卖出该 lot 的 100%。
3. 尾仓 lot 之间互相独立，不参与以后任何成本计算。除第 10 条基本面处理外，不做其他操作。
4. 没有 TP2。

数学性质：TP 成交时收回 0.75 × 1.25 = 0.9375 倍本轮成本，所以尾仓的净资金占用只有本轮成本的 6.25%。尾仓在 2×C 卖出时，再收回 0.5 倍本轮成本，整轮合计 1.4375 倍。

---

## 7. TP 成交：立即开新一轮

1. 撤掉本轮所有未成交买单，包括已挂出的深代买单。
2. 新 A = TP 实际成交价；GEN = 1；新 G = (该币可用现金 − 插针单预留) ÷ 3。利润就这样自动滚入下一轮。
3. 按第 5 条挂新的三张买单。

---

## 8. 深跌：最多三代，然后停止

1. 当前代的 B3 成交后，下一代锚点 **A_next = B3 成交价 × 0.80**。在 A_next 下方按 −7% / −17% / −35% 挂三张，每张 G/3。
2. **每轮最多 3 代**。第 3 代的 B3 成交后，不再挂任何新买单，只等 TP，或等人工基本面复核。
3. 深度参照（相对第一代锚点，B3 按挂单价成交时）：

| 代 | 三张买单的位置 | 未来 365 天内跌到该位置的历史频率（AAVE/LINK/TAO，收盘价口径 / 含盘中插针口径） |
|---|---|---|
| 第 1 代 | −7% / −17% / −35% | 92% / 83% / 64%（盘中 96% / 91% / 75%） |
| 第 2 代 | −52% / −57% / −66% | 45% / 37% / 20%（盘中 55% / 49% / 33%） |
| 第 3 代 | −75% / −78% / −82% | 9% / 7% / 3%（盘中 18% / 14% / 9%） |

这些是历史频率，不是对未来的预测。

4. 第 2 代及以后的买单，与第 1 代一起合并进同一个 C（第 6 条）。
5. 不等反弹再挂，不缩小深代金额，不改用平均成本做锚点。这三种做法在测试中都更差。
6. 进入第 2 代或第 3 代时，人工复核一次基本面。这是检查，不是开关。只有发现第 10 条列出的问题才 PAUSE。

---

## 9. 插针单（独立模块）

1. 金额 S，挂在 **A × 0.40**（−60%）。
2. 成交后，按其成交价 × 1.40 挂卖单，全部卖出。卖出后在当时的 A × 0.40 重新挂上。
3. 不并入 C，不留尾仓。未成交时随 A 同步移动。
4. 插针单要求订单一直挂在交易所上。闪崩通常在一小时内结束，手动反应来不及。

---

## 10. 基本面与暂停（人工，最高优先级）

出现以下任一情况，立即进入 PAUSED：

- 严重安全漏洞
- 协议失效
- 商业逻辑崩塌
- 代币经济明显恶化
- 大规模异常解锁
- 流动性严重下降
- 监管导致商业模式失效
- 交易所发布下架公告

PAUSED 时：

1. 撤掉全部未成交买单，包括插针单。
2. 不再越跌越买。
3. 重新研究，然后决定持有、恢复或退出。
4. 如果是下架，在下架前卖出或转出全部持仓。

代币迁移、改名或拆分（例如 RNDR → RENDER）：撤单，按新代码和换算比例重建 A、C 和尾仓卖单。

**价格本身不触发 PAUSE。** 测试过的"弱于 BTC""BTC 熊市时停止加仓"等纯价格规则，没有稳定的样本外优势。

---

## 11. 执行

1. 买单和卖单都提前挂好（Maker）。不追价，不加 execution buffer。差一点没成交，属于正常结果。
2. 每天检查一次就够。自动化程序可以每 1–4 小时同步一次成交。成交后需要的新单在下一次检查时挂出。
3. 已经越过目标价、但当时没有挂单的情况：
   - 卖：现价 ≥ 目标价，就按当前价挂单卖出；
   - 买：不追。按原价挂单等待。
4. 手续费约每边 0.1%，不是决策变量。

## 12. 每日流程（机器）

```
FOR 每个币（PAUSED 的币跳过买入相关步骤）:
    同步成交
    IF 买单成交:
        更新 C、Q；撤旧 TP，挂 TP = 1.25C（卖 75%）
        IF 成交的是本代 B3 且 GEN < 3:
            GEN += 1
            A_next = B3 成交价 × 0.80
            挂下一代三张（每张 G/3）
    IF TP 成交:
        剩余 25% → 尾仓 lot，挂 2 × C_lot 卖单
        撤本轮全部未成交买单
        以 TP 成交价为新 A，开新一轮（第 7 条）
    IF 尾仓 lot 卖单成交: 记账
    IF 插针单成交: 按第 9 条处理
    日收盘：IF 本轮无任何成交 AND 收盘价 ≥ 1.20 × A: 上调 A 并重挂

最后输出:
    Σ(未成交买单) + Σ(持仓成本) + Σ(未挂出的后续代预算)，对照 ΣB
    无任何触发时输出："今天无需操作。"
```

规则冲突时的优先级：

1. 基本面 / PAUSED
2. 预算上限 B
3. 成交同步
4. 更新 C 与上方卖单
5. TP 后开新一轮
6. 挂下一代
7. 慢速上调 A
8. 无操作

---

## 13. 年度复核（人工，每年一次）

1. 只看三样：基本面、流动性排名、上市时长。
2. 不按近期涨幅、反弹力度或"过去 12 个月循环次数"换币。测试显示，这些指标对下一年没有预测力，甚至方向相反。
3. 新币或历史不足 2 年的币，先只做卫星（小 B）。

## 14. 记录与复盘

保留 V2 第 46 条的全部字段，另加以下字段：

- GEN、所在代深度
- 每个尾仓 lot 的 C_lot 和 2× 目标
- 插针单成交记录

半年后重点复盘：

- 各档真实成交率
- TP 平均等待天数
- 尾仓 2× 触发率
- 第 2、3 代触发频率
- 资金占用率
- 手续费占利润的比例

只有真实交易数据证明某条规则长期明显低效，才修改它。

可以给每笔交易打上 HH/HL/LH/LL 加波动率状态的标签，但只用于记录，不影响下单。目前没有证据表明它能提高收益。

## 15. 已作废的 V2 规则（不得再使用）

- 按币种不同的三档百分比（HYPE 6/12/23、AAVE 7/17/29、TAO 7/19/30、LINK 6/14/25）
- 40% / 35% / 25% 的仓位比例
- TP2 = 1.50 × C 卖 25%，以及"TP2 成交后上调锚点"
- 永久尾仓（"除非基本面失效，否则 Tail 不参与循环"）
- 不设上限、靠每代人工判断"YES/NO"的代数规则；第 4 代及以上
- 下一代以 B3 成交价为锚点、且不设间隔的做法（现在必须先下移 20%）
- 整套卫星规则：FAST_1 / FAST_2、+15% / +30%、+20% 卖 75%、按币回补距离 d（NEAR 7% / ZRO 9% / PENDLE 9% / RENDER 8%）、回补批次 +20% 全卖
- "卫星仓初始市价买入"
- "每个币过去 12 个月少于 2 轮循环就换掉"
- "按近期表现或修复能力把卫星升级为核心"
- "每组单独止盈"。成本口径统一为本轮合并的 C
